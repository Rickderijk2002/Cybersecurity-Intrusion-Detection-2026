03

The protocol

DNS gets out of almost every network

Allowed out

DNS leaves almost every network and is rarely inspected.

Relayed for you

The resolver passes any name on to the server that owns the domain.

Never cached

A repeated name never reaches the attacker, so every query needs a new name.

How a tunnel normally travels. In our capture the client reached the tunnel server directly, on the same network segment.

04

Discovery

One domain gives itself away

  • 6 times more unique names than any other domain.
  • Its longest name is 252 bytes. DNS allows 255. The longest normal name is 103.
  • The only domain asked for NULL records.
  • Every query comes from one host, 10.0.2.30, which asks for nothing else.

Name lengths counted in bytes on the wire, not as Zeek prints them.

09

Attack mechanics

What a tunnel cannot hide

Any DNS tunnel shows these

Hard to change

  • Many new names under one domain
  • Long, random-looking names
  • A steady stream of queries, even when idle
  • Answers that carry data

Only this tool, or this lab

Easy to change

  • iodine's start-up letters and VACK
  • Queries sent straight to the attacker
  • One source port, TTL 0, EDNS0

173 of the 222 tunnel queries are short pings that look normal on their own. So the detector has to judge the domain, not the single query.

10

Detection

Four features, none about the tool

name_bytes

Name length

Long names carry data. Counted in bytes, as on the wire.

uniq_names_300s

Unique names

Different names asked under one domain in the last 5 minutes.

uniq_ratio_300s

Share of new names

Normal sites repeat names. A tunnel almost never does.

norepeat_tol

No repeats yet

The log of unique names times the share of new names, with no time window.

Left out on purpose: IP addresses, source port, answer flags, TTL, EDNS0 and record type. They separate this capture perfectly and say nothing about tunnels.

Counted per client and parent domain, from the earlier queries only. Report section 3.1.

The model

One tree: cut at random until alone

The idea

Pick a random feature and a random value, cut, and repeat in each box until every query is alone.

Tunnel query: 1 cut

Far from the crowd, so the first cut already sets it apart.

Normal query: 4 cuts, not alone

Inside the crowd, it keeps sharing a box.

Few cuts = strange

The ringed query needs 5 cuts. Fewer cuts means more anomalous.

Made-up example with 13 queries. No labels needed: the trees only see normal traffic.

12

The model

A forest of 300 trees turns cuts into a score

1 · 300 trees

Each tree cuts its own random sample of 256 normal training queries, as on the previous slide.

2 · Average the cuts

Over all trees, a normal query needs about 11 cuts, a tunnel query about 4.5.

3 · Cuts become a score

Fewer cuts, higher score. Past the line (5.3 cuts): alert.

Average number of random cuts per test query, 300 second window, one seed. Report Figure 3.1.

13

Training

Trained on normal traffic only

Normal only

The forest learns what normal DNS looks like. The tunnel is never in training.

Time order

Neighbouring queries are near copies, so a random split would leak.

Line from validation

The threshold is the highest score of any normal validation query.

The first burst is left out: it is an exact copy of the second, so it would be tested twice.

16

Choices

A longer window, fewer false alarms

  • Recall stays almost the same: 98.69% and 98.65%.
  • PR AUC is almost the same: 0.9931 and 0.9934.
  • 88% fewer false-positive queries.
  • We chose 300 seconds after seeing the test period. That is a limit, not a result.

Final: the validation maximum as threshold gives 3.3 false-positive queries.

Bars: threshold from five time ordered folds. Mean of ten seeds. Report section 3.3.

19

Limits

What the numbers do not prove

Holds up

Tested

  • The same result on ten random seeds
  • A tunnel 60 times slower: 98.3% still found
  • An alert on the fourth query of a session

Does not carry over

Limits

  • One tunnel session, one normal host
  • Window and threshold chosen after seeing the test period
  • Tunnels at 0.1% of traffic: precision falls to about 32%
  • Little training data: false alarms rise from 4.79% to 25.90%
  • Nine extra normal clients: false incidents rise from 1.8 to 9.6

A retrospective benchmark, not an independent validation. Real traffic would need new data.

20

Mitigation

Make DNS leave through one door

Prevention

Only the resolver may send DNS out. Refuse or flag NULL records, cap unique names per client.

Detection

Run the detector on resolver logs, plus cheap rules such as NULL queries.

Response

Isolate the client, keep the logs, then decode the tunnel to see what went through.

MITRE mitigations M1037 and M1031. Report section 4.
