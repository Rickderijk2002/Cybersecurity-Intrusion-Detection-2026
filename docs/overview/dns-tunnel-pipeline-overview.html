The setup and why

Keep one tunnel copyCopy 2 matches copy 1 byte for byte. Keeping both doubles the positives and makes copy 2 look like repeated names.
Default keeps copy 2 (18:50)It sits inside busy period 2, the harder test. Training can then include busy period 1.
Count per client and domainThe context features ask: how many names did this machine ask this domain? Same values here (one benign client); correct for networks with many hosts.
Cut at 18:30Middle of the quiet gap. Train: 1,592 benign rows, no tunnel. Test: 1,609 benign + 222 tunnel.

Strict variant: keep copy 1, cut at 18:04:36. Training is only 244 quiet rows, so it mostly shows what a load change does.

The features

Default: domain context (3)uniq_names_60s uniq_ratio_60s norepeat_tol
Caching forces a new name per query. A 60 s window plus a long memory that survives a repeated name. Catches the whole session, pings included.
Default: name shape (1)name_bytes
Data travels in the name, so names are long. Catches data and probe queries, not pings. One feature on purpose: the three shape features correlate about 0.8.
Ablation columns (5)longest_label entropy redundant with name_bytes. norepeat_evidence breaks on one repeated name. log_cum_uniq drifts with time. data_qtype (NULL or TXT) is iodine specific.

Left out on purpose: IPs, ports, flags, TTL, EDNS0, rtt, NXDOMAIN, raw volume, domain names. They separate the classes only because of the lab.

Why this feature set

Isolation Forest fitted on benign training rows, PR AUC on the test rows (mean of 10 seeds, threshold-free). Primary = tunnel copy 2; strict = copy 1 with only 244 training rows. One tunnel event, so read the direction, not the decimals.

More shape features rank worse because they are redundant and take splits from the context features. norepeat_tol carries the ranking. norepeat_evidence scores a little higher on clean data but one repeated name switches it off (see below), so it is an ablation. Running it

python main.py                      default: copy 2, cut 18:30, 60 s window
python main.py --all --tests        default + strict variant, then the checks
python main.py --window 60 300 900  several window sizes (slow tunnels)
python main.py --session first      only copy 1

data/processed/ is not in git: run python main.py first (needs data/raw/dns.log from Canvas). Then start with features.csv. Columns: split (train/test), y (label), 4 default features plus 5 ablation columns. Features are raw, not scaled. Default set: feature_sets(60)["forced"].

Suggested modelling

  1. Fit Isolation Forest on the default features, training rows only.
  2. Choose the threshold without the test rows: a percentile on a benign validation slice. Tukey on the training scores is poorly calibrated here (about 170 benign rows flagged in the primary run), so treat it as a baseline.
  3. Evaluate on test: precision, recall, F1, recall per phase, event-level metrics (time to first alert), and look at the false positives.
  4. Compare with simple baselines (a rule on uniq_names_60s is strong) and one alternative model. Then the ablations, window sizes, other cuts and the variants.

Limits to state

  • One tunnel session, one tool, one benign client. The simulations are built from this one capture and show robustness, not generalisation.
  • The tunnel is loud, so results will look strong. Slow and noisy variants are the real test.
  • The first 28 tunnel queries (12%) stay within the benign range of uniq_names_60s. 6.5% of rows are tunnel, so precision is optimistic.
  • The feature set is a starting point: name_bytes as the only shape feature rests on redundancy, and the numbers are mixed.
