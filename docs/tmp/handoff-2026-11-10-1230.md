## The labels

- **Rule:** `tunnel` when the query name ends in `pirate.sea`, else `benign`. 444 tunnel, 3,201 benign (12.2% tunnel).
- **`row_id` is the 0-based position of the row among the data rows of `dns.log`, in file order**: skip the `#` header lines, do not sort first. The log is not in time order, so if you sort by `ts` before joining, the labels end up on the wrong rows. Join first, sort afterwards:

```python
import pandas as pd

lines = open("data/raw/dns.log", encoding="utf-8").read().splitlines()
cols = next(l for l in lines if l.startswith("#fields")).split("\t")[1:]
df = pd.DataFrame([l.split("\t") for l in lines if not l.startswith("#")], columns=cols)  # index 0..3644 = row_id
df = df.join(pd.read_csv("data/labels.csv", index_col="row_id"))
df = df.sort_values("ts")  # only after the join
```

## Warnings for slices 2 to 5

1. **The second burst is a byte for byte replay of the first.** Same 222 names in the same order, same transaction IDs, same port, even the same answers. So there are 222 real tunnel queries, each present twice. Keep both copies of a name on the same side of any train and test split (or deduplicate), otherwise the metrics are inflated. A split on time puts identical rows on both sides.
2. **Do not use host identity as a feature:** IP address, resolver and source port separate the classes perfectly, so a model that uses them learns nothing about tunnelling. The report (2.3, rows 6 to 8) also keeps the other lab-specific signals out of the model: iodine's start-up letters, direct queries to the server (AA and RA flags), the fixed source port, TTL 0 and EDNS0.
3. **Choose the name length deliberately:** wire bytes (from the PCAP) or log characters (from `dns.log`). They differ by up to 3 times for the tunnel and not at all for benign names. The report uses wire bytes; say which one you use.
4. **NXDOMAIN does not mark this tunnel:** all 11 NXDOMAIN rows are benign.
5. **Query volume does not find it:** the benign client peaks higher (598 against 221 queries per minute).
6. **A 12.2% tunnel share is high for an anomaly detector.** Discuss the base rate and the `contamination` setting with it in mind.
7. **Zeek does not log message size or EDNS0.** Those come only from the PCAP (tunnel queries advertise EDNS0 4,096; no benign query uses EDNS0).
8. **Per-query length and entropy miss most of the tunnel.** 173 of the 222 tunnel queries are pings with short names, as short as normal names (median 19 against 20 bytes). Only the 24 data queries and 13 size probes are long and random looking (median entropy 5.75 against 2.52 bits per character for normal queries; over all tunnel queries it is 2.75). Domain and window level features (unique names per parent domain, queries per domain per minute) catch the whole session; plan for them.
