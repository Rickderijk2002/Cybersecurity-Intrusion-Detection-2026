## Design choices to document in the report (3.2)

- **Training rows are benign only.** The split in `src/prepare.py` puts the tunnel in the test period. This is anomaly detection: the model learns what normal DNS looks like, and the tunnel is never seen in training. Anything that differs from normal gets a high score.
- **Threshold from a benign validation slice:** the last `val_frac` (20%) of the training period, in time order. Not random: the rolling-window features make neighbouring rows near copies, so a random slice would leak. The forest is fitted on the rows before the slice. Test rows are never used to choose anything.
- **`contamination` is not used** (it replaces the "contamination sweep" from the task division). With benign-only training it would mean "flag a fixed share of normal traffic". The threshold table and the folds answer the same question: how do the results change with the line?
- **score = -score_samples**, so higher = more anomalous (sklearn's own sign is the reverse).
- **Time-ordered folds** as a robustness check for the line: training cut into 5 consecutive blocks with equal row counts, each held back once, its highest score is that block's line. Like 5-fold cross-validation, but in time order and used to set the line, not to measure accuracy.
- **Defaults:** 300 trees, `max_samples="auto"` (256 rows per tree), `max_features=1.0`, `random_state=0`. Every run with the same data and settings gives the same result; report the seed and settings with the numbers.

## For slice 6 and the theoretical evaluation (3.4)

- **Evasion by domain rotation:** the context features count per (client, parent domain). An attacker who spreads the tunnel over many domains (e.g. a new domain every ~25 queries, below the benign maximum) keeps each pair under the normal level. Cost for the attacker: many registered domains, each with its own authoritative server; newly seen domains are suspicious in themselves. Counter-features: per client across all domains (unique names per machine per minute, number of new parent domains).
- **Slow tunnels:** a 60 s window misses a tunnel that sends one query every 10 s; `norepeat_tol` (no window) partly covers that.
- **The line depends on network load** (see the folds): in a real network it would need regular recalibration.

## Decisions for the group

1. **Default threshold:** keep `val_max`, or switch to `folds_max` with the reasoning "no normal row in any training block alerts" (stated independently of the test results; be open in the report that the comparison table was seen).
2. **Window:** 60 s (Thom's default) or 300 s (earlier draft: 1 FP instead of 58, same recall). Changes the feature defaults, so Thom decides with the group.
3. **Combined feature idea for Thom:** Yahoo has many unique names but repeats them (ratio about 0.25); the tunnel never repeats. Isolation Forest cuts one feature at a time and does not use this combination. Something like unique names × ratio might remove the Yahoo false positives.
4. **Full `main.py` at the end:** one entry point for features + detector + printout (e.g. `python main.py --detect`), and `tests/test_detector.py` added to `--tests`. `main.py` is Thom's file.

## Warnings

- Do not choose a threshold, seed, feature set or setting because it gives the best numbers on the test rows. The threshold table, the folds per block and the parameter check are for comparison and explanation only.
- `data/processed/` is git-ignored: `scores.csv` and the plot are made locally by running the code.
- `feature_importance` uses the labels: it explains the model, it must not be used to choose features.
